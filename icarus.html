> Das Warum (Motivation)

Als jahrelange Windows-Nutzerin war ich nie wirklich zufrieden mit dem System; nach ersten Spielereien mit Linux habe ich dann Ende 2024 beschlossen, komplett umzusteigen und Linux als mein Main-OS zu nutzen. Seither läuft das auch super, ich bin mega zufrieden und lerne jeden Tag dazu.

Mein Problem war bisher nur: Ich konnte zwar den ganzen Müll entfernen und das System exakt so anpassen, wie ich es mochte; allerdings musste ich bei jedem Rechner wieder komplett von vorne anfangen. Sachen deinstallieren, Programme einrichten, Themes anpassen; das hat einfach genervt. Als ich dann durch Bazzite auf BlueBuild gestoßen bin, dachte ich mir: Das ist die perfekte Idee, um einfach mein komplett eigenes, deklaratives OS-Image zu bauen.

> Struggles & Lessons Learned
[CRITICAL] System is far from working yet.
[WARN] Declarative thinking required; procedural commands invalid.
[ERROR] GitHub Actions Build failed after 10m: Invalid path token.

Der größte Struggle ist hierbei definitiv das deklarative Denken. Wenn man ein normales OS konfiguriert, tippt man einfach stumpf Befehle ein; bei einem immutablen OS via BlueBuild musst du aber vorher schon exakt wissen, welche Datei am Ende in welchem Pfad landen soll, bevor das Image überhaupt in der Cloud gebacken wird. Ein einziger falscher Pfad im Build-Skript, und die GitHub Action bricht nach 10 Minuten gnadenlos ab.

Besonders das geplante, eigene OOBE-Portal hat im Kopf schon einige Nerven gekostet; aber der Lerneffekt in Sachen Container-Infrastruktur und Linux-Dateisysteme ist jetzt schon unbezahlbar.
